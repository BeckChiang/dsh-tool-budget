# dsh-tool-budget

给 [DeepSeek Harness](https://github.com/topics/deepseek-harness) 用的**会话级工具预算**：决定模型这一轮能看见哪些工具，并估算「换掉工具要重送多少上下文、每轮净省多少 token」。

它不是「把工具关掉」的开关，而是一套带成本的预算表：

- **省 token**：工具清单（名字 + 说明 + 参数）是每一轮都要重发的固定开销。隐藏一个组，每轮都少发那几百上千字符。
- **提高命中**：工具少而精时，模型更容易选对；但关错了会让它拿不到需要的能力。
- **可回退**：三档级别 + 三种模式，最坏情况是模型停下来说明缺什么，你一键恢复。

> **血缘**：本项目的调用次数统计、面板骨架与遮罩机制来自 [dsh-tool-switch 0.3.0](https://github.com/suqing114/dsh-tool-switch)（MIT，作者 suqing114）。在此基础上重写为按「方案 / 场景包 / 分组 / 插件」管理，并加入成本估算、建议集、学习包与三档级别。上游改动可以逐步合并，接口不兼容处已按本项目的结构重写。

## 安装

```bash
# 本地开发（软链，改完刷新页面即可）
dsh plugin install link:C:/path/to/dsh-tool-budget

# 从市场 / npm（发布后）
dsh plugin install dsh-tool-budget
```

装好后输入框下方出现「工具预算」按钮；点开就是面板。改 Host 半侧（`index.js`、`lib/*.js`）后要把插件重挂一次才生效；只改客户端（`lib/client.js`）刷新页面即可。

## 面板导读

从上到下六块，**标题栏与页脚常驻**，中间滚动：

1. **成本估算**（默认展开）：`+N token/轮` 的净省、四项明细、切换后每轮预估、可展开的公式与参数。
2. **建议**：近 30 天没调用过的组、被关着却仍在用的组，各带「休眠 / 恢复」按钮。
3. **模式**：`auto` / `ask` / `pin`，每个模式一行说明。
4. **方案**：六个内置方案 + 你的自定义方案 + 学习出来的方案。
5. **工具列表**：按分组或按插件两种视图；每行可切三档级别、看调用次数与参数签名、展开完整说明。
6. **页脚**：学习状态与「开始学习」。

标题栏右侧显示 `开 N / 降 M / 关 K`；每个分组卡片头也有一组同样含义的小胶囊。

## 三档级别

| 级别 | 对模型 | 对调用 | 用途 |
| --- | --- | --- | --- |
| **正常** normal | 看得见 | 可以调 | 默认 |
| **降权** warn | 看得见 | `guard` 拒绝，并返回你写的理由 | 想留个后手，但希望少用 |
| **隐藏** hidden | 看不见 | 从执行集合里移除，调用直接失败 | 真正省 token |

两条硬规则：

- **核心**（`tool_budget`、`present`、`ask_user_question`）永远是正常，不允许关——关掉 `tool_budget` 就没人能帮你恢复，关掉 `present` 交付物出不来。
- **受保护**（`read`/`write`/`edit`/`ops_bash`/`grep`/`glob`/`working_directory` 等）可以关，但必须再确认一次——它们关掉后模型基本没法干活。

> 由 agent 作用域注册的工具（面板里标「会话固定」）不受遮罩影响，这是框架限制，不是本插件的取舍。

## 成本估算：数字从哪来

### 三个输入

1. **工具清单字符数**：每个工具的 `name + description + 完整参数 JSON` 长度，直接从 `ctx.tools.definitions()` 取（合并全局与 agent 作用域两份）。隐藏的组求和 = `hiddenChars`。
2. **当前上下文 token**：读本会话日志 `~/.dsh/sessions/**/session.v4.jsonl.zstd` 里 `usage` 行，取 `input + cacheRead` 的最大值（真实值，不是估算）。
3. **历史平均每轮 token**：同一批 `usage` 行的均值，用来算红色阈值。取不到时退回「日志字符数 ÷ 每 token 字符数」，并标记为估算值。

### 公式

```
saved   = hiddenChars / charsPerToken        省下的输入 token（每轮）
repay   = (context − toolBlock) × missFactor 改清单后首轮要重付的 token
net     = saved − 常驻                        每轮净省
常驻     = auto 模式 200，ask / pin 模式 20；固定，不可改
projected = avgTurn − saved + 常驻             切换后预计每轮输入
红色阈值 = avgTurn × thresholdMultiplier       首轮重付超过它就该停下来想想
```

为什么首轮要重付：工具清单在前缀里，**一改就从工具块之后全部失效**，缓存命中的那部分按全价重算一次。所以「会话开头决定」最省，中途反复微调最亏。

### 可改的五个参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `charsPerToken` | 3.6 | 每 token 多少字符；中英混排的粗估 |
| `missFactor` | 1 | 首轮重付的折扣：1 = 全价，0.1 = 假设九成还能命中 |
| `thresholdMultiplier` | 2 | 红色阈值 = 平均每轮 × 这个倍数 |
| `priceInput` | 2 | 输入价（元 / 百万 token），只用于显示金额 |
| `priceCache` | 0.2 | 缓存价（元 / 百万 token） |

误差来源：字符/token 比随语言浮动、描述长度随工具版本变化、缓存命中率取决于前缀是否真的没变。**这是相对比较用的估算，不是账单。**

## 建议是怎么生成的

只做建议，永不自动生效。规则两条：

1. **休眠建议**：某组全部工具近 30 天一次都没调用过，且组里不含核心/受保护工具 → 建议休眠。按可省 token 数降序，最多 8 条。
2. **恢复建议**：某组现在被隐藏，但 30 天内有调用记录 → 建议恢复（说明之前关错了）。

为什么不做「按频率自动关」：频率不等于价值。`present`、`ask_user_question`、`interrupt_agent` 可能一辈子 0 次，缺了就直接卡死。所以关不关由你点，插件只负责把「省多少、为什么」写清楚。

点「休眠」只把那一组设为隐藏；点「恢复」把它拉回正常。都可以撤销。

## 模式如何起作用

| 模式 | 提示词里多出什么 | 缺能力时 | 每轮常驻 |
| --- | --- | --- | --- |
| **ask**（默认） | `tool_budget` 的描述里有一句「被隐藏的组可以恢复」 | 模型停下来说明「需要 X，请恢复」，你点一下 | 20 |
| **pin** | 什么都不说 | 模型不知道有这些工具，也不会自己恢复；错了要你手动开 | 20 |
| **auto** | `tool_budget` 的完整使用说明（含休眠概念） | 模型自己调用 `tool_budget on <组>` 恢复，继续干活 | 200 |

- 三档都省 token，区别在「出错后谁来收拾」：`ask` 最省且可控，`auto` 最省心但每轮多 200 token，`pin` 适合明确知道要什么的短任务。
- `auto` 下模型自愈的前提是它能调用 `tool_budget`——所以核心工具永远不关。
- 模式是全局偏好，改了对下一条消息生效。

## 方案（原「场景包」）

方案 = 一份「留哪些组/插件」的预设。内置六个：

| 方案 | 保留 | 适合 |
| --- | --- | --- |
| 全部保留 | 全部 | 默认、不确定时 |
| 只留基础 | 会话与计划、终端与执行 | 只想聊天/改文件 |
| 代码 + 文件 | 会话、终端、文件、工具链、网页 | 写代码 |
| 查资料 + 网页 | 会话、网页、工具链、MCP 资源 | 检索、调研 |
| 图像 + 设计 | 会话、图像与音视频 | 出图 |
| 办公文档 | 会话、办公、文件 | docx/xlsx/pptx |

### 选包 = 按预设重来

点一个包会把该会话的**精细调整（逐工具/逐组/逐插件）一并清空**，否则会出现「选了全部保留却还有工具关着」。再点第二个包会与第一个叠加；「全部保留」是互斥的全开状态——选了别的包它就灭，把最后一个包点掉才回来。

### 自定义方案

- **存为方案**：把当前状态（包 + 三级精细调整）一起存成一份 `manual` 方案，输入名字即可。以后点它原样恢复。
- **复制学习包**：学习出来的包只读。想改就从它复制一份，改副本，原件保持不变（避免你的改动影响下一次学习）。
- **删除**：只删自定义/学习包，内置包不可删。

### 学习包怎么来的

点「开始学习」后：

1. 扫描 `~/.dsh/sessions/**/session.v4.jsonl.zstd`，只取**当前工作区**（按首条会话记录的 `cwd` 过滤）、最近 180 个、单个 < 32MB 的会话日志。
2. 每个会话记录「实际被调用过哪些组」，得到一个组集合。
3. 两两算 Jaccard 相似度，≥ 0.5 的并成一簇（贪心，先密后疏）。
4. 一簇至少 4 个会话才产出；覆盖率（簇内会话数 / 抽样会话里出现过该组的比例）≥ 0.6；最多 6 个组。
5. 按支持会话数取前 3 个包，包名用组的中文名拼（如「文件、命令、网页」），带来源与置信度：`来源：本工作区 N 个会话，置信度 M`。

状态机：`idle → learning → ready | failed`；`learning.json` 版本不符或旧格式（组 id 拼接）会被判过期并隐藏。学习只产出**建议**，不会自动切换。

> 置信度 = 这些组同时出现的会话比例，不是「推荐程度」。

## 工具分类与计数

### 分组（18 组）

`会话与计划`、`终端与执行`、`文件与检索`、`网页与检索`、`子代理与编排`、`办公与文档`、`图像与音视频`、`MCP 资源`、`社交与消息`、`工具链与维护`、`其他`，以及按工具名前缀兜底出来的 `x:<prefix>` 组（如 `x:create`）。分类规则在内置映射表里，MCP 工具按 `mcp__<server>__` 自动归到 `mcp:<server>`。

### 插件（工具从哪来）

没有权威的「来源」字段，所以按三级判定：

1. MCP 前缀 `mcp__<server>__` → `mcp:<server>`；
2. 内置前缀映射：`ops_` → dsh-ops，`dsh_doctor` → dsh-doctor，`mnemon_` → dsh-mnemon，`unlag_` → dsh-unlag，搜索族 → dsh-free-search，图像族 → dsh-image-gen，`tool_budget` → dsh-tool-budget；
3. 单下划线前缀兜底 `x:<prefix>`，其余归「其他」。

### 计数（三个口径）

| 口径 | 数据源 | 用途 |
| --- | --- | --- |
| 本会话 | 当前会话日志的 `tool/call` | 判断这个任务里用没用过 |
| 30 天 | 同一工作区全部日志，按天分桶 | 判断「最近还用过吗」 |
| 全局 | 全部日志累计 | 判断长期习惯 |

计数只走 UI 与建议，**不写进提示词**——否则工具描述会随使用变化，前缀缓存每轮都失效。扫描有缓存（`usage-cache.json`，按文件 size + mtime 命中），冷扫 200+ 日志约 5 秒，之后毫秒级。

> 高频 ≠ 该留，低频 ≠ 该删。`present` 一辈子 0 次也不能关；某个搜索工具 500 次也可能只是上周调研用得多。

## 工具、命令与 HTTP

- **工具** `tool_budget`：`action` = `list | on | off | warn | reset | profile | pack | cost`，`target` 支持组 id/标签、插件、包名、方案名、工具名、前缀、通配、`all`。
- **命令** `/budget`：`list`、`reset`、`all on`、`all off`、`on <target>`、`off <target>`、`warn <target>`。
- **HTTP**（仅回环，无鉴权）：`/tool-budget/state`（GET 读、POST 改）、`/tool-budget/usage`、`/tool-budget/cost`、`/tool-budget/learning`、`/tool-budget/preferences`。

数据文件都在 `~/.dsh-tool-budget/`：`budget.json`（会话状态与方案）、`usage-cache.json`（调用次数缓存）、`learning.json`（学习结果）。

## 边界

- **只影响当前会话**：没有「全局默认」，换会话要重新选。这是刻意的，避免一次误关影响所有任务。
- **改清单会破一次前缀缓存**：见成本一节。开头切一次最划算。
- **关掉的工具就是看不见**：`restrict()` 会同时从 schema、PTC 绑定、执行集合里移除，调用返回 `UNKNOWN_TOOL`，文案由框架生成。
- **agent 作用域注册的工具关不掉**（面板标「会话固定」）。
- **成本是估算**：相对比较可靠，绝对值有 ±20% 左右的浮动。
